Capítulo 5. Crear paquetes de R y de Python

NotaObjetivos
  • Entender cuándo merece la pena convertir el código de un proyecto en un paquete.
  • Conocer la estructura de un paquete de R y el flujo con usethis, roxygen2 y testthat.
  • Conocer el equivalente en Python (pyproject.toml, uv, pytest) y cómo publicar y citar el software.

Lectura obligatoria

Marwick, B.; Boettiger, C.; Mullen, L. (2018). Packaging data analytical work reproducibly using R (and friends). The American Statistician, 72(1), 80-88.

1. ¿Por qué un paquete?

Un paquete es la forma estándar de distribuir código reutilizable con su documentación, sus pruebas y sus dependencias declaradas. Merece la pena cuando:

  • Usas las mismas funciones en varios proyectos (copiar y pegar acaba en versiones distintas).
  • Quieres que otras personas usen tu método.
  • Quieres que el software sea citable y reconocido como resultado de investigación.

Marwick, Boettiger y Mullen (2018) van más allá y proponen organizar todo un proyecto de análisis como un compendio de investigación: una estructura de paquete que reúne datos, código, documentación y manuscrito, de modo que las herramientas del ecosistema (comprobaciones, pruebas, integración continua) sirvan también para garantizar la reproducibilidad.

2. Un paquete de R

bibliometrica/
├── DESCRIPTION        nombre, versión, autores (con ORCID), licencia, dependencias
├── NAMESPACE          qué se exporta (lo genera roxygen2)
├── R/                 las funciones
├── man/               la ayuda (la genera roxygen2)
├── tests/testthat/    las pruebas
├── vignettes/         tutoriales largos
├── inst/CITATION      cómo citar el paquete
└── README.md

El flujo habitual con usethis y devtools:

usethis::create_package("~/bibliometrica")
usethis::use_mit_license()
usethis::use_r("indice_h")          # crea R/indice_h.R
usethis::use_testthat()
usethis::use_test("indice_h")       # crea tests/testthat/test-indice_h.R
usethis::use_package("jsonlite")    # declara una dependencia
usethis::use_git(); usethis::use_github()
devtools::document()                # roxygen2 → man/ y NAMESPACE
devtools::test()                    # ejecuta las pruebas
devtools::check()                   # R CMD check: la revisión completa

Una función documentada con roxygen2 y su prueba con testthat:

#' Índice h de una serie de citas
#'
#' @param citas Vector numérico de citas, una por publicación.
#' @return Un entero: el mayor h tal que h publicaciones tienen al menos h citas.
#' @examples
#' indice_h(c(10, 8, 5, 4, 3))
#' @export
indice_h <- function(citas) {
  stopifnot(is.numeric(citas), all(citas >= 0, na.rm = TRUE))
  citas <- sort(citas[!is.na(citas)], decreasing = TRUE)
  sum(citas >= seq_along(citas))
}

# tests/testthat/test-indice_h.R
test_that("indice_h funciona en casos conocidos", {
  expect_equal(indice_h(c(10, 8, 5, 4, 3)), 4)
  expect_equal(indice_h(numeric(0)), 0)
  expect_error(indice_h(c(-1, 2)))
})

R CMD check revisa la documentación, los ejemplos, las pruebas, las dependencias y docenas de detalles; CRAN exige que pase sin errores ni avisos. Para publicar, las opciones son CRAN (revisión estricta, máxima difusión), R-universe (publicación inmediata desde GitHub) y la revisión por pares de rOpenSci para paquetes científicos. La web de documentación se genera con pkgdown.

3. Un paquete de Python

bibliometrica/
├── pyproject.toml     metadatos, dependencias y sistema de construcción
├── src/bibliometrica/
│   ├── __init__.py
│   └── indices.py
├── tests/test_indices.py
└── README.md
uv init --package bibliometrica     # crea la estructura con pyproject.toml
uv add requests                     # dependencia
uv add --dev pytest                 # dependencia de desarrollo
uv run pytest                       # pruebas
uv build                            # construye el paquete
uv publish                          # publica en PyPI (con un token)

4. Versiones, citas y DOI

  • Versionado semántico (MAJOR.MINOR.PATCH): sube el PATCH al corregir errores, el MINOR al añadir funciones compatibles y el MAJOR al romper la compatibilidad.
  • Añade un CITATION.cff (lo leen GitHub y Zenodo) y, en R, inst/CITATION.
  • Conecta el repositorio con Zenodo para obtener un DOI por versión, y cita el software en tus artículos con su versión y su DOI.

Ejercicios

Ejercicio 5.1 · Validar las entradas (R)

Completa la función para que rechace las citas negativas con stopifnot(), y comprueba que devuelve el índice h correcto.

Las citas deben ser mayores o iguales que cero: >=.

indice_h <- function(citas) {
  stopifnot(is.numeric(citas), all(citas >= 0, na.rm = TRUE))
  citas <- sort(citas[!is.na(citas)], decreasing = TRUE)
  sum(citas >= seq_along(citas))
}
indice_h(c(12, 0, 45, 7, 3, 10, 28, 1))

Ejercicio 5.2 · Pruebas con assert (Python)

Escribe la función normaliza_doi para que pasen las tres pruebas. La última línea devuelve True si todo va bien.

Para pasar a minúsculas se usa .lower().

def normaliza_doi(doi):
    """Minúsculas, sin espacios, sin prefijo de URL ni 'doi:'."""
    doi = doi.strip().lower()
    for prefijo in ("https://doi.org/", "doi:"):
        if doi.startswith(prefijo):
            doi = doi[len(prefijo):]
    return doi.strip()

assert normaliza_doi("10.1/ABC") == "10.1/abc"
assert normaliza_doi(" https://doi.org/10.1/x ") == "10.1/x"
assert normaliza_doi("DOI: 10.1/Y") == "10.1/y"
True

En un paquete, estas pruebas irían en tests/test_doi.py y se ejecutarían con uv run pytest.

Caso práctico resuelto

NotaDe tres scripts a un paquete en una mañana

Tres proyectos copian las mismas funciones (normaliza_doi, indice_h, lee_openalex). Pasos:

  1. usethis::create_package("bibliometrica").
  2. Mover cada función a R/ con documentación roxygen2 y @export.
  3. Declarar dependencias: usethis::use_package("jsonlite").
  4. Una prueba por función con casos normales y extremos.
  5. devtools::check() hasta 0 errores, 0 avisos y 0 notas.
  6. Sustituir el código copiado en los proyectos por library(bibliometrica).
  7. GitHub + Zenodo para la versión 0.1.0 con DOI.

Resultado: un único lugar donde corregir errores, documentación accesible con ?indice_h y un software citable.
