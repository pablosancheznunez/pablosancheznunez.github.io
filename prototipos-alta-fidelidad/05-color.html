Tema 5. Uso accesible del color

NotaObjetivos
  • Aplicar nociones de teoría del color a las interfaces.
  • Construir paletas accesibles que cumplan los contrastes mínimos de las WCAG.
  • Diseñar para las personas con daltonismo y tener en cuenta los significados culturales del color.

1. Teoría del color para interfaces

Un color se describe mejor, para diseñar, por su tono (la posición en el círculo cromático), su saturación (intensidad) y su luminosidad (claridad). Las combinaciones clásicas (análogas, complementarias, triádicas) son un punto de partida, pero en las interfaces el color tiene sobre todo funciones:

  • Marca: identifica el producto.
  • Jerarquía: atrae la atención hacia la acción principal.
  • Semántica: comunica estados (error, aviso, éxito, información).
  • Agrupación: relaciona elementos.

Una paleta de interfaz suele tener un color primario, uno o dos de acento, los colores semánticos y una escala de grises para textos, bordes y fondos, cada uno en varios tonos más claros y más oscuros.

2. Contraste: los mínimos de las WCAG

El contraste se mide con la relación de contraste de las WCAG, calculada a partir de la luminancia relativa de los dos colores: va de 1:1 (iguales) a 21:1 (negro sobre blanco). Los mínimos de nivel AA son:

Qué Mínimo AA Mínimo AAA
Texto normal 4,5:1 7:1
Texto grande (desde 24 px, o 18,66 px en negrita) 3:1 4,5:1
Componentes de interfaz y gráficos (bordes de campos, iconos que transmiten información, foco) 3:1 —

El contraste depende de la luminosidad, no del tono: un naranja y un azul muy saturados pueden tener poco contraste entre sí y con el blanco.

3. Daltonismo

Alrededor del 8 % de los hombres y del 0,5 % de las mujeres de ascendencia europea tienen alguna deficiencia en la visión de los colores. Las más frecuentes afectan al eje rojo-verde (protanopía y deuteranopía, y sus formas parciales); la tritanopía (azul-amarillo) es rara. Machado, Oliveira y Fernandes (2009) propusieron un modelo basado en la fisiología de los conos que permite simular cómo ve los colores una persona con cada deficiencia, y es el que usan muchas herramientas de diseño.

Las reglas prácticas:

  • No transmitir información solo con el color (criterio 1.4.1 de las WCAG): los estados llevan además icono y texto; los enlaces, subrayado o forma; los gráficos, etiquetas o texturas.
  • Comprobar que los colores que deben distinguirse lo hacen también por luminosidad.
  • Simular la paleta antes de cerrarla.

4. Consideraciones culturales

Los significados del color no son universales. El rojo es peligro o error en muchas interfaces occidentales, pero se asocia a la suerte y la celebración en China; el blanco es luto en partes de Asia oriental; el verde tiene connotaciones religiosas en algunos contextos. En productos internacionales conviene apoyarse en las convenciones de la plataforma, acompañar el color de iconos y texto, y comprobar los significados con personas de cada mercado.

Práctica en R: revisar una paleta

Ejercicio 5.1

El azul primario #1a73e8 cumple por muy poco el 4,5:1 sobre blanco. ¿Y su versión oscura #174ea6 sobre el gris muy claro de fondo #f1f3f4? Calcula el contraste.

El color del texto es la versión oscura del primario: #174ea6.

contraste("#174ea6", "#f1f3f4")

Unos 7: cumple incluso el nivel AAA para texto normal. Los fondos grises claros restan contraste, así que conviene comprobar cada combinación real, no solo sobre blanco.

Ejercicio 5.2

Simula con protanopía los colores de aviso (acento) y error de la paleta, y calcula cuánto se distinguen por luminosidad.

El tipo para la protanopía es «protan».

d <- simular_daltonismo(paleta_ejemplo[c("acento", "error")], tipo = "protan")
d
distinguibles(d[1], d[2])

Unos 2,6: con protanopía, el rojo de error se oscurece y el naranja del acento se vuelve amarillo, así que se distinguen por luminosidad, aunque sin llegar al 3:1 que se pide a los componentes. El problema grave de esta paleta está entre el error y el éxito, que quedan casi iguales (Tema 12 del libro de baja fidelidad).

Laboratorio: contraste y daltonismo

Laboratorio · cálculo en tu navegador

Elige un color de texto y uno de fondo. El laboratorio calcula la razón de contraste de las WCAG 2.2, te dice qué niveles cumple y simula cómo ven la combinación las personas con los tres tipos principales de daltonismo (matrices de Machado, Oliveira y Fernandes, 2009).

color = window.Lab.color
viewof c_texto = color("Color del texto", {value: "#e8663a"})
viewof c_fondo = color("Color del fondo", {value: "#ffffff"})
{
  const rgb = h => [1, 3, 5].map(i => parseInt(h.slice(i, i + 2), 16) / 255);
  const lin = c => c <= 0.04045 ? c / 12.92 : Math.pow((c + 0.055) / 1.055, 2.4);
  const L = h => { const [r, g, b] = rgb(h).map(lin); return 0.2126 * r + 0.7152 * g + 0.0722 * b; };
  const ratio = (a, b) => { const [x, y] = [L(a), L(b)].sort((p, q) => q - p); return (x + 0.05) / (y + 0.05); };
  const M = {protan: [[0.152286, 1.052583, -0.204868], [0.114503, 0.786281, 0.099216], [-0.003882, -0.048116, 1.051998]],
             deutan: [[0.367322, 0.860646, -0.227968], [0.280085, 0.672501, 0.047413], [-0.011820, 0.042940, 0.968881]],
             tritan: [[1.255528, -0.076749, -0.178779], [-0.078411, 0.930809, 0.147602], [0.004733, 0.691367, 0.303900]]};
  const sim = (h, t) => { const v = rgb(h).map(lin), m = M[t];
    const o = m.map(f => Math.min(1, Math.max(0, f[0] * v[0] + f[1] * v[1] + f[2] * v[2])));
    return "#" + o.map(c => Math.round(255 * (c <= 0.0031308 ? 12.92 * c : 1.055 * Math.pow(c, 1 / 2.4) - 0.055)).toString(16).padStart(2, "0")).join(""); };
  const r = ratio(c_texto, c_fondo);
  const marca = ok => ok ? "✓ cumple" : "✗ no cumple";
  const muestra = (t, f, et) => `<svg viewBox="0 0 160 92" style="flex:1;min-width:9rem;max-width:14rem" role="img" aria-label="${et}: texto ${t} sobre fondo ${f}, contraste ${ratio(t, f).toFixed(2).replace(".", ",")} a 1"><rect x=".5" y=".5" width="159" height="91" rx="6" fill="${f}" stroke="#bbb"/><text x="10" y="20" font-size="11" fill="${t}">${et}</text><text x="10" y="46" font-size="19" font-weight="600" fill="${t}">Reservar</text><text x="10" y="66" font-size="13" fill="${t}">Texto de ejemplo</text><text x="10" y="84" font-size="11" fill="${t}">${ratio(t, f).toFixed(2).replace(".", ",")}:1</text></svg>`;
  const d = html`<div role="status"></div>`;
  d.innerHTML = `<p style="font-size:1.2rem"><strong>Contraste ${r.toFixed(2).replace(".", ",")}:1</strong></p>
  <ul><li>Texto normal, AA (4,5:1): <strong>${marca(r >= 4.5)}</strong></li><li>Texto grande, AA (3:1): <strong>${marca(r >= 3)}</strong></li>
  <li>Componentes y gráficos, AA (3:1): <strong>${marca(r >= 3)}</strong></li><li>Texto normal, AAA (7:1): <strong>${marca(r >= 7)}</strong></li></ul>
  <div style="display:flex;gap:.5rem;flex-wrap:wrap" class="lab-muestras">${muestra(c_texto, c_fondo, "Visión típica")}${muestra(sim(c_texto, "protan"), sim(c_fondo, "protan"), "Protanopia")}${muestra(sim(c_texto, "deutan"), sim(c_fondo, "deutan"), "Deuteranopia")}${muestra(sim(c_texto, "tritan"), sim(c_fondo, "tritan"), "Tritanopia")}</div>
  <p class="small mt-2">Con las funciones del libro: <code>contraste()</code>, <code>cumple_wcag()</code> y <code>simular_daltonismo()</code>. Prueba el naranja por defecto: muy visible, pero no llega a 4,5:1 sobre blanco. Busca el naranja más parecido que sí cumpla.</p>`;
  return d;
}

Laboratorio: modo oscuro

Laboratorio · se ejecuta en tu navegador

El modo oscuro no es invertir los colores. El fondo no debe ser negro puro (cansa y produce halos), el texto no debe ser blanco puro y el color de marca suele necesitar una versión más clara para mantener el contraste. Elige tu color de marca y mira las dos versiones.

colorO = window.Lab.color
viewof marca = colorO("Color de marca", {value: "#1c6b3a"})
{
  const hex = (h) => [1, 3, 5].map((i) => parseInt(h.slice(i, i + 2), 16));
  const lin = (c) => { c /= 255; return c <= 0.04045 ? c / 12.92 : Math.pow((c + 0.055) / 1.055, 2.4); };
  const L = (h) => { const [r, g, b] = hex(h).map(lin); return 0.2126 * r + 0.7152 * g + 0.0722 * b; };
  const R = (a, b) => { const [x, y] = [L(a), L(b)].sort((p, q) => q - p); return (x + 0.05) / (y + 0.05); };
  const mez = (h, d, t) => "#" + hex(h).map((c, i) => Math.round(c + (d[i] - c) * t).toString(16).padStart(2, "0")).join("");
  const ajusta = (c, fondo, destino) => { for (let t = 0; t <= 1.0001; t += 0.02) { const x = mez(c, destino, t); if (R(x, fondo) >= 4.5) return x; } return mez(c, destino, 1); };
  const claro = {fondo: "#ffffff", sup: "#f4f4f2", texto: "#1a1a1a", sec: "#52514e", marca: ajusta(marca, "#ffffff", [0, 0, 0])};
  const oscuro = {fondo: "#121212", sup: "#1e1e1e", texto: "#e8e8e6", sec: "#b5b4b0", marca: ajusta(marca, "#1e1e1e", [255, 255, 255])};
  const f = (v) => v.toFixed(1).replace(".", ",");
  const tarjeta = (m, nom) => `<figure class="m-0"><div style="background:${m.fondo};padding:14px;border-radius:12px;border:1px solid var(--bs-border-color)"><div style="background:${m.sup};padding:14px;border-radius:10px"><div style="color:${m.texto};font-weight:600;font-size:18px">Sala 2.14</div><div style="color:${m.sec};font-size:14px">6 personas · planta 2</div><div style="margin-top:10px;display:inline-block;background:${m.marca};color:${R(m.marca, "#ffffff") >= 4.5 ? "#ffffff" : "#121212"};padding:8px 14px;border-radius:8px;font-weight:600">Reservar</div> <span style="color:${m.marca};font-weight:600;margin-left:8px">Ver normas</span></div></div><figcaption class="small text-center mt-1">${nom}</figcaption></figure>`;
  const fila = (n, m, s) => `<tr><td>${n}</td><td>${f(R(m.texto, m.sup))}:1</td><td>${f(R(m.sec, m.sup))}:1</td><td>${f(R(m.marca, m.sup))}:1 <code>${m.marca}</code></td></tr>`;
  const css = `:root {\n  --fondo: ${claro.fondo}; --superficie: ${claro.sup};\n  --texto: ${claro.texto}; --texto-sec: ${claro.sec}; --marca: ${claro.marca};\n}\n@media (prefers-color-scheme: dark) {\n  :root {\n    --fondo: ${oscuro.fondo}; --superficie: ${oscuro.sup};\n    --texto: ${oscuro.texto}; --texto-sec: ${oscuro.sec}; --marca: ${oscuro.marca};\n  }\n}`;
  const d = html`<div role="status" aria-live="polite"></div>`;
  d.innerHTML = `<div class="row g-3"><div class="col-sm-6">${tarjeta(claro, "Modo claro")}</div><div class="col-sm-6">${tarjeta(oscuro, "Modo oscuro")}</div></div>
  <table class="table table-sm mt-2"><thead><tr><th scope="col">Modo</th><th scope="col">Texto</th><th scope="col">Texto secundario</th><th scope="col">Marca (enlace)</th></tr></thead><tbody>${fila("Claro", claro)}${fila("Oscuro", oscuro)}</tbody></table>
  <p>${claro.marca.toLowerCase() !== marca.toLowerCase() ? `Tu color no llegaba a 4,5:1 sobre blanco: se ha oscurecido a <code>${claro.marca}</code>. ` : ""}En modo oscuro la marca pasa a <code>${oscuro.marca}</code> para mantener el contraste.</p>
  <pre><code>${css}</code></pre>`;
  return d;
}

Fíjate en que la elevación en modo oscuro se expresa aclarando la superficie (#1e1e1e sobre #121212) y no con sombras, que apenas se ven sobre fondos oscuros.

Caso práctico resuelto

NotaColores que cumplen WCAG

Paleta inicial: botón verde claro (#6BCB77) con texto blanco. Comprobación de contraste: alrededor de 2:1, no cumple el mínimo de 4,5:1 para texto normal (WCAG 2.1 AA).

Solución: oscurecer el verde hasta superar 4,5:1 con texto blanco, o usar texto oscuro sobre el verde claro. Además:

  • La disponibilidad no se indica solo con color: «Libre» / «Ocupada» en texto e icono.
  • Se comprueba la paleta con simuladores de daltonismo (protanopia, deuteranopia).
  • El modo oscuro tiene su propia paleta, comprobada de nuevo, no una inversión automática.

Ejercicios graduados

Básico. ¿Qué contraste mínimo exige WCAG 2.1 AA para texto normal y para texto grande?

4,5:1 para texto normal y 3:1 para texto grande (unos 24 px, o 18,5 px en negrita). Los componentes de interfaz y gráficos necesitan 3:1 con su entorno.

Avanzado. Diseña la leyenda de disponibilidad de salas para que funcione en escala de grises.

Combinar color con texto («Libre», «Pocas horas», «Ocupada»), iconos distintos y, si se usan barras, patrones o rellenos diferentes. Comprobarlo convirtiendo la pantalla a grises.

AdvertenciaErrores frecuentes
  • Comprobar el contraste a ojo en una pantalla brillante.
  • Elegir la paleta de marca y luego «arreglar» la accesibilidad: comprueba el contraste al definir los colores.
  • Olvidar el modo oscuro: los mismos colores no funcionan igual sobre fondos oscuros.
  • El gris claro sobre blanco para textos secundarios: elegante, pero a menudo ilegible.

Reto evaluable

ImportanteReto del Tema 5 · Paleta accesible del proyecto

Para tu proyecto:

  1. Define la paleta con sus funciones: primario, acento, semánticos y grises, con varios tonos de cada uno.
  2. Comprueba con revisar_paleta() el contraste de cada combinación de texto y fondo que uses, y corrige las que no cumplan.
  3. Simula la paleta con protanopía, deuteranopía y tritanopía y comprueba que los pares que deben distinguirse lo hacen; indica qué otros medios (icono, texto, forma) acompañan al color.
  4. Revisa los significados culturales de tus colores para el público del proyecto.

Entrega: un informe hecho con la plantilla de entrega. Se evalúa con la rúbrica que incluye la plantilla. Este reto no tiene solución en el libro: cada estudiante trabaja con un proyecto distinto y la corrección la hace el profesorado.
