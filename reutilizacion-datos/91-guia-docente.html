Apéndice C — Guía para el profesorado

Cómo encaja el libro con Aula Global

El libro es material de estudio y práctica; la evaluación sigue en los cuestionarios de Aula Global. Cada capítulo prepara la actividad evaluable de su tema:

Capítulo Actividad de Aula Global Qué practica el libro
Tema 0 «Clasifica y audita» Estrellas, Open Definition y auditoría del CSV
Tema 1 «Del derecho de acceso a la reutilización» Cronología de normas, plazos de la Ley 19/2013, datos de alto valor
Tema 2 «WebQuest de reutilización» Dimensiones de Safarov et al.; lectura de la ficha ODM 2025
Tema 3 «Laboratorio de calidad con OpenRefine» Completitud, duplicados, municipios, fechas y total de Getafe en R
Tema 4 «Taller de datos enlazados» Turtle, JSON-LD y consultas sobre un grafo fijo
Tema 5 «Caso de empresa infomediaria» Patrones de negocio y obligaciones de licencias

Para enlazarlo desde Aula Global basta un recurso URL por tema que apunte al capítulo correspondiente. También puede incrustarse un capítulo en una Página con un <iframe>, aunque la lectura es más cómoda en pestaña aparte.

El conjunto de datos de práctica

El fichero datos/prestamos_bibliotecas_practica.csv de este libro es sintético. Si en Aula Global se usa otra versión del CSV, sustituye el fichero de la carpeta datos/ por esa versión con el mismo nombre y vuelve a publicar. Las comprobaciones de los ejercicios que dependen del CSV (Primeros pasos, Temas 3, 4 y 5) calculan la respuesta esperada a partir del fichero, así que se adaptan solas, con dos condiciones:

  • Las columnas deben llamarse igual (id, biblioteca, municipio, fecha, prestamos, usuarios_activos).
  • La tabla de equivalencias de municipios (forma_correcta, en los Temas 3, 4 y 5) y la tabla de población ficticia del Tema 5 debe incluir todos los municipios del fichero.

Glosario, descargas y autoevaluación

  • Glosario (92-glosario.qmd): términos agrupados por tema, cada uno con un ancla #gl-.... Cada capítulo tiene un recuadro «Glosario del tema» con enlaces a sus términos. Para añadir uno, crea un encabezado ### Término {#gl-termino} en la sección del tema y enlázalo como [Término](92-glosario.qmd#gl-termino).
  • Descargas (carpeta plantillas/): un script .R limpio por capítulo, la plantilla de informe informe_practica.qmd y su tema informe.scss. Los scripts se generan a partir de los bloques {webr} de cada capítulo con python3 herramientas/extraer_r.py .; vuelve a ejecutarlo si cambias el código de un capítulo.
  • Autoevaluación: preguntas con el formato de webexercises, mediante la extensión local _extensions/webex/, que genera el mismo marcado sin necesidad de R al renderizar:
::: {.webex-check .webex-box}
1. Pregunta de verdadero o falso {{< torf true >}}
2. Desplegable: {{< mcq "*correcta" "incorrecta" "incorrecta" >}}
3. Hueco: {{< fitb "respuesta" "alternativa" ignorecase=true >}}
4. Opciones en lista:

{{< longmcq "incorrecta" "*correcta" >}}
:::

::: {.webex-solution boton="Ver explicaciones"}
Texto que se despliega con el botón.
:::

El asterisco marca la opción correcta. Los huecos no pueden ir dentro de código en línea: escribe el código antes y después, por ejemplo `sum(x` {{< fitb ">" >}} `2)`.

Figuras y versión en PDF

  • Figuras (carpeta figuras/): una o dos por tema, en SVG, generadas con python3 herramientas/figuras.py . (necesita Python con matplotlib). Usan una paleta categórica validada para el daltonismo y llevan texto alternativo en el capítulo. Si cambias el CSV de práctica, vuelve a generarlas.
  • PDF (pdf/reutilizacion-datos-abiertos.pdf): se genera con python3 herramientas/pdf.py, que une los capítulos y los compila con Typst, incluido en Quarto, sin LaTeX. El filtro _extensions/libro-pdf/ adapta el contenido al papel: muestra el código sin ejecutar, convierte pistas y soluciones en recuadros, presenta las preguntas sin corrección automática y transforma los enlaces entre capítulos en enlaces internos. Genera el PDF antes de quarto render, para que se copie al sitio.

Orden para publicar una edición nueva:

python3 herramientas/extraer_r.py .   # scripts .R de cada capítulo
python3 herramientas/figuras.py .     # figuras
python3 herramientas/moodle.py .      # banco de preguntas para Aula Global
python3 herramientas/pdf.py           # PDF
quarto render                         # sitio web en _book/

Banco de preguntas para Aula Global

Las preguntas de autoevaluación de cada capítulo (49 en total) se exportan a Moodle XML con python3 herramientas/moodle.py ., que deja en la carpeta moodle/ un fichero por capítulo y otro con todo el banco. Cada pregunta conserva su explicación como retroalimentación general. Para usarlas como cuestionario calificado: Banco de preguntas → Importar → Moodle XML.

  • Banco completo (Moodle XML)

Tipos: verdadero/falso, opción múltiple con respuesta única y respuesta corta. Las respuestas cortas que aceptan variantes (con y sin tilde, en mayúsculas o minúsculas) las incluyen todas.

Caso práctico y datos reales

El caso práctico usa una copia del conjunto «Bibliotecas de Madrid» del Ayuntamiento de Madrid (CC BY 4.0), descargada el 24 de noviembre de 2026 y sin modificar: datos/bibliotecas_madrid_2026-11-24.csv. El portal lo actualiza a diario; para actualizar el caso, descarga una copia nueva, cambia el nombre del fichero en el capítulo y en herramientas/extraer_r.py, y vuelve a ejecutar las pruebas: las comprobaciones de los ejercicios calculan la respuesta a partir del fichero.

Accesibilidad, analítica y comprobación automática

  • Accesibilidad. El libro se ha revisado con axe-core contra WCAG 2.1 AA sin incidencias. El fichero accesibilidad.html añade nombres accesibles a los editores de código y a los controles interactivos, y estilos.scss ajusta el contraste de pies de figura y citas.
  • Analítica. El libro carga /consent.js de la web: Google Analytics y Microsoft Clarity solo se activan si el visitante acepta las cookies, y la elección es la misma en toda la web. Fuera de pablosancheznunez.com el script no existe y no se carga nada.
  • Comprobación automática. El flujo .github/workflows/comprobar.yml genera el libro en cada cambio y ejecuta en un navegador real los ejercicios de webR, las preguntas de autoevaluación y la auditoría de accesibilidad (herramientas/pruebas/). Si algo falla, el cambio aparece con una cruz roja en GitHub.

Retos evaluables

Cada tema termina con un reto evaluable pensado para la evaluación continua en Aula Global. A diferencia de los ejercicios, no tiene pista, solución ni corrección automática, y cada estudiante trabaja con datos distintos (un portal, una palabra de búsqueda o un conjunto elegido por él), lo que dificulta copiar. La entrega es un informe hecho con la plantilla informe_practica.qmd y se corrige con su rúbrica (pesos 15/25/20/20/10/10).

Tema Reto Funciones de datareuseR
0 Auditoría de apertura de tres conjuntos de publicadores distintos estrellas()
1 Solicitud de reutilización con cálculo de plazos y festivos reales sumar_habiles()
2 Radiografía de un tema en datos.gob.es con la API en directo consultar_datosgob(), tabla_datosgob()
3 Limpieza documentada de un CSV real (≥100 filas) leer_csv_abierto(), informe_calidad(), clave_agrupacion()
4 Publicación de diez registros como JSON-LD y del conjunto con DCAT-AP —
5 Propuesta de servicio infomediario con tres escenarios obligaciones(), punto_equilibrio()

Las soluciones de referencia y los criterios de corrección de cada reto no están en el repositorio público: se entregan aparte al profesorado. Si las guardas en el repositorio, hazlo en una rama o un repositorio privado.

Actividades interactivas y laboratorios

Desde la versión 1.4, cada tema incluye actividades de corrección inmediata (ordenar, clasificar y escenarios con decisiones) y laboratorios que se usan sin programar: compatibilidad de licencias, comprobador de calidad de un CSV (que también acepta los ficheros del estudiante, sin que salgan de su navegador) y conversión de CSV a JSON y a RDF. En el PDF y el EPUB las actividades aparecen en papel, con su solución. Las actividades están escritas en Markdown con la extensión interactivos (_extensions/interactivos/interactivos.lua), así que se pueden añadir o cambiar sin programar.

Cada tema tiene además diapositivas de clase (objetivos, figuras, tablas principales, lectura, preguntas para debatir y reto) en diapositivas/; se generan con python3 herramientas/diapositivas.py después de quarto render.

Progreso, uso sin conexión y modo oscuro

  • Progreso del estudiante (progreso.html): cada capítulo muestra cuántos ejercicios ha resuelto y cuántas preguntas ha acertado el estudiante, y la presentación resume todos los capítulos. Se guarda en el almacenamiento local del navegador (localStorage), sin cookies ni envío a ningún servidor: el profesorado no lo ve. Sirve de autorregulación, no de evaluación.
  • Uso sin conexión (sw.js): un service worker guarda las páginas, webR y sus paquetes la primera vez que se visitan. Las páginas se piden primero a la red y, si no hay conexión, se sirven desde la copia; el resto, al revés. Al publicar una versión nueva, cambia VERSION en sw.js.
  • Modo claro y oscuro: el interruptor junto al título, en la barra lateral, cambia entre los dos; por defecto se respeta la preferencia del sistema. El tema oscuro está en estilos-oscuro.scss y también se audita con axe-core.
  • PDF y EPUB: python3 herramientas/pdf.py genera los dos formatos; el EPUB lleva portada, metadatos (DOI, licencia) y la misma ficha del libro que el PDF.

El paquete datareuseR

La carpeta datareuseR/ contiene un paquete de R con los datos y las funciones auxiliares del libro, documentado y con pruebas (R CMD check --as-cran sin errores ni avisos). El libro no puede instalarlo dentro de webR, así que python3 herramientas/datareuser_webr.py genera datos/datareuseR.R con sus funciones, y los capítulos lo cargan con source(). Si cambias el paquete, vuelve a ejecutar ese script. Los estudiantes pueden instalarlo con remotes::install_github("pablosancheznunez/reutilizacion-datos", subdir = "datareuseR"); para publicarlo en CRAN basta con enviar la carpeta del paquete.

Publicar y actualizar el libro

El libro es un proyecto de Quarto con la extensión quarto-live, que ya va incluida en la carpeta _extensions/. Los capítulos usan engine: markdown, así que para renderizar no hace falta R instalado: el código se ejecuta en el navegador del estudiante.

quarto preview          # vista previa local
quarto render           # genera el sitio en _book/

Opciones de publicación:

  • GitHub Pages: el repositorio incluye .github/workflows/publicar.yml, que renderiza y publica el libro en cada push a main. En Settings → Pages, elige GitHub Actions como origen.
  • Cualquier servidor web: sube el contenido de _book/. Debe servirse por HTTP(S); abrir index.html con doble clic no funciona, porque webR necesita un servidor.

Mantenimiento

  • Datos que cambian cada año: el Tema 2 remite a la ficha del Open Data Maturity 2025 y el Tema 5 al informe de ASEDIE. El libro no incluye esas cifras, solo los enlaces; basta con actualizar los enlaces cuando salga una nueva edición.
  • DCAT-AP-ES y NTI-RISP: antes de cada curso, comprueba si la NTI modificada se ha publicado en el BOE y ajusta el párrafo del Tema 3.
  • Versión de webR: el libro sirve webR 0.6.0 desde su propia carpeta webr/ y los paquetes desde webr-repo/, sin depender de servidores externos. Para actualizarlo, sustituye esas carpetas por la nueva distribución de webR y los binarios correspondientes, y cambia VERSION en sw.js para que los navegadores renueven su copia.
  • Fuentes externas: el flujo .github/workflows/semanal.yml comprueba cada lunes los enlaces del libro, el CSV de bibliotecas de Madrid y la API de datos.gob.es, y comprueba el paquete datareuseR con la consulta en directo. Si algo falla, abre una incidencia en GitHub con el informe; también puedes ejecutarlo a mano con python3 herramientas/comprobar_fuentes.py.

Añadir un ejercicio

Un ejercicio autocorregido tiene hasta cuatro bloques con la misma etiqueta exercise:

```{webr}
#| exercise: mi_ejercicio
#| setup: true
datos <- read.csv("datos/prestamos_bibliotecas_practica.csv")
```

```{webr}
#| exercise: mi_ejercicio
nrow(______)
```

::: {.solution exercise="mi_ejercicio"}
`nrow(datos)`
:::

```{webr}
#| exercise: mi_ejercicio
#| check: true
if (identical(.result, nrow(read.csv("datos/prestamos_bibliotecas_practica.csv")))) {
  list(correct = TRUE, message = "Correcto")
} else {
  list(correct = FALSE, message = "Revisa el objeto que cuentas")
}
```

En el bloque check, .result es el valor de la última línea del código del estudiante y .user_code es el texto del código. La documentación de quarto-live explica más opciones.
